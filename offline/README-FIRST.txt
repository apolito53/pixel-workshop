PIXEL WORKSHOP OFFLINE + MCP - WINDOWS X64 (PILOT)
==================================================
This archive is an internal QA pilot. Do not sell or distribute it until
the release checklist and user authorization are complete.

GET STARTED
1. Extract the ZIP into a normal writable folder. Do not run from inside ZIP.
2. Double-click PixelWorkshop.cmd. The browser should open once the loopback
   server is ready; otherwise visit http://127.0.0.1:4317 manually.
3. Create a workspace in the browser and start a 32 x 32 canvas.
4. Pixel files stay under %LOCALAPPDATA%\PixelWorkshop\data.
5. Use the editor's Export panel to save PNG, SVG, sprite sheet and project files.
6. Close the terminal window (or press Ctrl+C) to stop the server.
7. Uninstall by deleting the extracted folder. Delete the separate data folder
   only if you ALSO want to erase your locally saved projects.

AGENT/MCP CONNECTION
The locally hosted MCP endpoint is http://127.0.0.1:4317/mcp.
It requires your workspace Bearer token to keep projects isolated.

With a workspace open in the browser, use the workspace's agent-token action
(or browser's supported token setup UI) to retrieve a token. Configure an
MCP client that supports remote/streamable HTTP with endpoint above and
Authorization: Bearer <your-token> (protect it as a password).
The MCP client must be installed separately; no AI model, hosted inference,
API subscription or credits are included.

Smoke workflow: call create_canvas(32x32), paint a pixel, then export_png or
export_svg. Confirm that the generated bytes load in your game project.

SECURITY AND LIMITS
This program binds only to IPv4 loopback (127.0.0.1). Never expose port 4317
through port forwarding, a proxy, or a public tunnel. The HTTP server uses
local files and the included Node runtime; no Node/pnpm install is needed.
It is not a sandbox for untrusted local programs. Do not give workspace tokens
to people or plugins you do not trust.

The Node runtime and production third-party dependencies are redistributed
with their accompanying license files. See NODE-LICENSE.txt,
DEPENDENCY-LICENSES.json and the licenses inside node_modules.
Project and component licensing must be reviewed before public sale.

This build has no installer, update service, code signing, auto-start,
cloud storage, support contract or guaranteed model-generated art quality.
Windows SmartScreen may warn about an unsigned downloaded package.
